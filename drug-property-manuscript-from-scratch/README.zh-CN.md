# 药物发现属性预测论文：从零成稿 Skill

**名称：** `drug-property-manuscript-from-scratch`<br>
**版本：** 1.0.0<br>
**对象：** 已有研究工作与实验材料，但没有完整手稿的作者。<br>
**默认输出：** 英文手稿与图表标签；中文诊断和修改说明。

## 1. 解决什么问题

输入可以是中文笔稿、零散记录、几段大致研究意图，以及已有的实验数据、图片、表格。无需先写成一篇中文论文，也无需先提供英文大纲。

本 skill 的目标不是把中文按句翻译，也不是凭一个题目虚构研究，而是：

**中文笔稿／研究意图 + 真实实验材料 → 研究事实与结论边界 → 适配的真实范文 → 具体写法拆解与迁移 → 论证和图表安排 → 实际小样 → 完整首稿。**

“从零”指从零组织和撰写手稿，不是从零编造方法、结果和科学贡献。没有结果时，只能提供明确标记的前结果写作框架，不能交付伪装成已完成实验的论文。

## 2. 与手稿重建 skill 的关系

| 维度 | 本 skill：from-scratch | 已有 skill：rebuild v2 |
|---|---|---|
| 起点 | 中文笔稿、大致意图、零散实验材料 | 已有手稿及图表 |
| 主要任务 | 恢复研究记录，首次组织论证并成稿 | 诊断旧稿并重建表达与视觉组织 |
| 对照对象 | 输入事实 + 同功能真实范文 | 旧稿 + 输入事实 + 同功能真实范文 |
| 共同要求 | 范文深读、迁移卡、实际图文、证据边界、成稿对照 | 同左 |
| 相互依赖 | 无，可独立完成完整初稿 | 无需为使用本 skill 而安装它 |

两者使用不同名称，可以并存。本包不修改或替换 rebuild v2；也不会在生成初稿后自动开启第二轮整稿重建。需要后续重建时，保留已有证据记录和编辑决策，避免重复整理。

## 3. 支持哪些入口

### 中文笔稿 + 实验结果 + 图片

先分清笔稿中的方法事实、观察结果、作者意图、解释、假设、未来计划和疑问；保留“可能”“尚未”“仅在部分数据集”等限定。再依据完整研究材料建立新的英文论证，而不是继承中文笔稿的句法和记录顺序。

笔稿可以是文本、提纲、幻灯片中的文字，也可以是实际手写记录。手写内容需有可用视觉读取能力；看不清的名称、数字、符号会标记不确定，不会猜成事实。

### 大致意图 + 实验结果 + 图片

把“我想证明什么”与“已经做出的实验支持什么”分别记录。若作者希望证明新靶点泛化，而已有实验仅为随机配对划分，就不会把结果改写成冷靶点评估；会给出证据允许的暂定主线并标明范围差距。

### 图片／表格为主

先读取实际图片及图注，恢复坐标、指标、分组和上下文。有完整源数据可重绘；只有清楚的图片可以复用、改写图注、按可见精度转录明确标签，但不能伪造原始预测、误差条或隐藏数值。

代码与逐样本预测是有帮助的可选输入，不是开始写作的强制条件。缺少它们时，会限制验证范围，而不是声称已经检查了实际训练过程。

## 4. 保留“真正学到范文”的核心机制

不会用“逻辑清晰、语言凝练、图表专业”替代具体分析。每项借鉴需要对应：

`真实论文及位置 → 可观察的组织做法 → 帮助读者理解什么 → 适用于本研究的条件 → 本稿具体段落／图表 → 检查实际输出是否落实。`

没有用户指定范文时，在具备且允许检索能力的环境中，使用不涉及未公开数据的关键词查找适配论文。范文按任务、贡献类型、证据丰富程度和读者选择，而不是只按刊名选择。

全篇主参考需要阅读全文；图表校准需要真正查看页面。只能读摘要时，不会声称完成了全文写法拆解；没有视觉能力时，不会声称看过排版与图片。缺失能力会被标明，但不妨碍输出证据允许的暂定稿。

## 5. 安装到 Codex

把 ZIP 解压得到的完整文件夹放到项目中：

```text
你的项目/
└── .agents/
    └── skills/
        ├── drug-property-manuscript-rebuild/       # 已有版本，可选
        └── drug-property-manuscript-from-scratch/  # 本次新增
            ├── SKILL.md
            ├── agents/
            ├── references/
            ├── assets/
            └── examples/
```

也可使用用户级 `$HOME/.agents/skills/`。路径与显式调用方式依据 2026-10-16 核对的 OpenAI 官方说明，见 [SOURCES.md](SOURCES.md)。当日原 Codex skills 文档重定向到 ChatGPT Learn 的 Build skills 页面。

必须保留完整 `references/` 目录；单独复制 `SKILL.md` 不足以运行所有阶段。不要额外嵌套两层同名文件夹。

本包的 `agents/openai.yaml` 将 `allow_implicit_invocation` 设为 `false`，用于避免与重建流程误触发。使用 `$drug-property-manuscript-from-scratch` 显式调用。Codex 通常自动发现新增或更新的本地 skill；未显示时再重启。

这是用于本地 Codex 的独立 skill 文件夹源目录，不是已经安装的应用，也不是经过审核的插件目录包。将它保存在仓库中不会自动安装到 Codex；实际使用时，请按上方路径复制到目标项目或用户级 skills 目录。

## 8. 图片复用与重绘的实际边界

已有图表会按事实条件选择复用、改图注、从源文件调整、从真实数据重绘、按已核实方法重设计或暂存待核实。不是所有图片都必须重画。

只有一张 ROC 图或一个 AUC 数值，并不意味着能够重算原始 ROC 曲线；只有均值，不代表能补上标准差。架构图可说明作者给出的流程，但不能证明某次训练确实使用了所有图中组件。

对于无法核实的细节，保留工作标记及问题清单。成稿可交付为“完整工作稿”，但不将其冒充为全部事实已核验、可直接投稿的最终版本。

## 9. 文件组成

- `SKILL.md`：主流程、输入路由、模式和交付要求。
- `agents/openai.yaml`：Codex 界面信息与显式调用策略。
- `references/01–06`：输入恢复、范文迁移、论证与英文写作、图表、审查交接、领域边界。
- `assets/`：可选输入单、研究简报、段落包、迁移卡、证据／结果／图表登记表、交接模板。
- `examples/`：两个明确虚构的教学示例，不是实验结果或真实范文。
- `EVAL_CASES.md`：拟进行的行为验收场景，不代表已经运行。
- `VALIDATION.md`、`validation-results.json`：本次实际静态检查范围。
- `.gitattributes`：固定文本文件换行格式，便于跨平台核对哈希。
- `SHA256SUMS`：包内文件哈希，用于完整性对照，不表示作者身份认证或安全保证。

## 10. 已检查与未验证

结构、YAML、内部文件引用、示例算术和打包完整性可以做确定性检查；具体结果见 [VALIDATION.md](VALIDATION.md)。

本次没有读取你的真实研究笔稿、实验数据或图片，没有安装到你的 Codex，没有生成你的论文，也没有以盲评验证其写作质量。文件检查和较详细的规范并不能证明实际稿件已经达到优秀论文的水平。实际效果需要同一套材料上的真实成稿比较。
