# 药物属性预测手稿重建 Skill v2.0

## 这次修订解决什么

上一版以手稿重建与科学一致性为主，对范文学习只要求一个简短风格画像。v2 将“从真实论文学到具体写法，并检验是否迁移成功”改为主流程：

**实际范文 → 逐段/逐图拆解 → 有来源的迁移卡 → 项目写作约定 → 真实小样 → 对照修订 → 全文重建。**

它不把“按照顶刊/顶会写”“语言更凝练”“图更专业”当作可执行的最终规格，也不把检查表完成、代码能运行或编译成功当作写作质量提升。

这不是模型微调，也不是已经验证有效的自动论文写作系统。没有真实稿件与范文对照测试前，不能保证消除用户感受到的差距。

## 安装到 Codex

解压后保留完整文件夹，放到项目中的：

```text
.agents/skills/drug-property-manuscript-rebuild/
```

也可使用用户级 `~/.agents/skills/`。通过 `$drug-property-manuscript-rebuild` 显式调用。安装方式依据 2026-10-16 核对的 OpenAI 官方文档，来源见 `SOURCES.md`。

这是同名 skill 的 v2 替代版。先备份旧版，再在自己的环境中替换；不要在多个发现路径同时保留同名启用版本，避免选择歧义。本次交付没有操作用户的 Codex，也没有覆盖旧版下载文件。

必须保留 `references/`：v2 使用按阶段加载的模块，而非可独立运行的单个 SKILL.md。没有强制依赖其他写作 skill，没有安装脚本，没有自动外传数据行为。绘图、联网和编译依赖实际 Codex 环境，skill 本身不提供这些工具。

## 建议首次只验收小样

```text
$drug-property-manuscript-rebuild

我的药物发现属性预测论文实验已完成。问题不是一般英文润色，
而是图表和整篇行文仍明显不像我认可的高质量计算类论文。

初稿、图表与实验资料位于：[真实路径]。
范文位于：[真实路径；没有则检索与本研究任务、贡献类型相近的公开论文]。
投稿对象：[填写；未确定则保留暂定计算类研究论文风格]。

本轮只做“范文拆解 + 校准小样”，不要直接重写全文。
请读取真实论文的完整相关段落，并查看图表页面。
说明具体借鉴哪一个段落/图表做法、为什么适用于我的研究、哪些不能借鉴。

交付一小段重写后的 Introduction、一个重写后的 Results 段落、
一张实际重绘的关键图和一个实际重排的主表；按现有材料调整范围。
把旧稿、小样与同功能范文做具体对照。不要只交写作建议。
没有的结果、误差条、机制或模型组件一律不补。
正文和图表标签用英文，分析用中文，保留所有原始文件。
```

当小样的方向得到认可后，再要求按确定的写作约定扩展全文。也可直接要求完整稿件：该模式仍会先做内部小样比较，但不会未经要求强制等待人工批准。

## 范文不需要很多，但必须适配

通常从 3–5 篇开始只是工作量建议，不是验证过的最优数目。可以使用一篇作为整稿主参考，其他论文只提供某类段落、架构图或结果表格的做法。不同体裁不能生硬拼合。

用户认可的范文优先。未指定范文时，skill 会在可用工具范围内自行查找，不会把全部检索工作推回给用户。只有摘要或解析文字时，必须如实限制能够完成的写作/视觉校准范围。

`examples/transfer-cards.md` 中的两篇公开论文仅演示拆解方法，不是为本篇研究已经选定的参考集，也不是最新论文推荐。`examples/synthetic-rewrite.md` 中的全部实验事实均为虚构教学示例。

## 如何判断它是否真的比上一版好

先看真实小样，而不是 skill 长度或自评分。对同一研究事实，检查段落是否更容易读出中心判断，Methods 是否解释了实际技术关系，图是否展示关键操作而不仅是模块名，表是否让比较更直接。

进一步验证时，以相同输入、篇幅和工具预算，比较原工作流与 v2；请不了解版本标签的读者进行成对评价，并单独检查事实错误。同一个模型换角色自评不能当成独立验收。

## 文件

- `SKILL.md`：主工作流与路由。
- `references/`：范文拆解、正文、视觉、对照评审及精简科学边界。
- `examples/`：实际阅读的迁移卡示例、同事实虚构改写示例。
- `assets/project-style-contract.md`：项目写作约定模板。
- `EVAL_CASES.md`：待执行的行为验收场景。
- `VALIDATION.md`：本次实际检查与未完成的验证。
- `SOURCES.md`：官方与原始来源、版本和访问范围。
